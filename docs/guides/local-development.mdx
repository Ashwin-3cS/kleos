## Mock mode, per axis

`ORCHESTRATOR_MODE=mock` is the default and needs no API keys. Three overrides
narrow it per axis, each `auto` by default:

| Variable | Values | Why it exists |
| --- | --- | --- |
| `CONNECTOR_FIXTURES` | `auto` \| `never` | `never` runs the real connectors while extraction and embedding stay keyless — how to check a parser against your own export without an LLM key |
| `EXTRACTOR` | `auto` \| `mock` \| `llm` | |
| `EMBEDDER` | `auto` \| `fake` \| `real` | |

## The three services

```bash
./scripts/services.sh up       # start, wait until each is answering
./scripts/services.sh status
./scripts/services.sh down     # stop and remove (volumes survive)
./scripts/services.sh reset    # down, then delete the volumes too
```

Ports: Neo4j `7688` (bolt) and `7475` (browser), Redis `6380`, Postgres `5435` —
all non-default, so they do not collide with anything already running.

<Warning>
The suite **skips** rather than fails when Neo4j is unreachable, so starting
pytest too early looks exactly like everything passing. `services.sh up` waits
for every port before returning, which is what makes
`services.sh up && pytest` honest.
</Warning>

`CONTAINER_CLI=podman` works.

## Upgrading a pre-rename checkout

Identifiers used to say `memorai`. The Neo4j constraint and index names and the
two Postgres tables are migrated automatically — the Neo4j migration creates the
new names and then drops the old ones, and the Postgres migration renames in
place, preserving every row.

Local containers cannot be migrated by the repository: the Neo4j password lives
inside its own data directory and the Postgres role was fixed when the volume was
initialised. `services.sh` detects a pre-rename set and refuses to start rather
than failing later as an authentication error against a database that looks
healthy.

<Tabs>
<Tab title="Migrate without losing data">
Change the stored credentials first, using the old ones:

```bash
docker exec memorai-neo4j cypher-shell -u neo4j -p memoraidev \
  "ALTER CURRENT USER SET PASSWORD FROM 'memoraidev' TO 'kleosdev'"

docker exec memorai-postgres psql -U memorai -d memorai \
  -c "CREATE ROLE kleos LOGIN SUPERUSER PASSWORD 'kleosdev'" \
  -c "CREATE DATABASE kleos OWNER kleos"
```

Then replace the containers, keeping the volumes:

```bash
docker rm -f memorai-neo4j memorai-redis memorai-postgres
./scripts/services.sh up
```

<Warning>
**Replace the container; do not rename it.** A container's environment *and its
healthcheck* are fixed when it is created, and `docker rename` changes neither.

A compose-created Neo4j runs `cypher-shell -u neo4j -p <old password>` every
five seconds. After the password changes, that healthcheck fails forever — and
because Neo4j rate-limits repeated authentication failures, the database then
rejects **correct** credentials too, in windows long enough to span a whole test
run. It reads as a wrong password, intermittently, indefinitely.

`docker restart` clears the lockout only until the next healthcheck. Replacing
the container is what ends it.
</Warning>

If `services.sh` created the originals, the volumes are `kleos-*-data` and are
reused as they are. If compose did, they are `orchestrator_*-data`, and a new
container starts empty unless you mount them explicitly:

```bash
docker run -d --name kleos-neo4j -p 127.0.0.1:7688:7687 \
  -e NEO4J_AUTH=neo4j/kleosdev -v orchestrator_neo4j-data:/data \
  neo4j:5.26-community
```
</Tab>
<Tab title="Start clean">
```bash
docker rm -f memorai-neo4j memorai-redis memorai-postgres
docker volume rm memorai-neo4j-data memorai-postgres-data
./scripts/services.sh up
```

Only if the contents are expendable. Neo4j rebuilds by re-ingesting, and the
token rows are mock consents.
</Tab>
</Tabs>

## Running the pieces by hand

```bash
.venv/bin/python -m orchestrator.api            # FastAPI on :8090
.venv/bin/python -m orchestrator.jobs.worker    # RQ worker
.venv/bin/python -m orchestrator.mcp_server     # MCP server over stdio
```

## Two devices, by hand

`scripts/orchestrator_smoke.sh` and `scripts/mcp_smoke.py` both prove the
cross-device flow with no model in the loop, which is what makes them
regression tests and what makes them useless for *watching* it work. Neither
leaves anything running afterwards.

```bash
./scripts/run_local.sh      # gateway + enclave
./scripts/hands_on.sh       # orchestrator, MCP over HTTP, two grants
```

`hands_on.sh` sets the same thing up and stops: an orchestrator serving the
tools over streamable HTTP, two device keys registered with the gateway, and two
grants signed by them — one that may write and supersede, one that may only
read. It prints the `claude mcp add` line and the text to paste into each chat,
then gets out of the way. Memory is deliberately **not** wiped, unlike the smoke
test: the point is that what one agent recorded outlives the session that
recorded it.

```bash
./scripts/hands_on.sh grants   # re-mint when the 8h TTL runs out
./scripts/hands_on.sh stop
```

<Note>
The MCP endpoint needs the **trailing slash** — `.../mcp/`. The app is mounted
at `/mcp` and its own endpoint inside is `/`, so `/mcp` redirects and a client
that drops the session header across the redirect fails in a way that reads like
a protocol bug.
</Note>

### Against a local model

Extraction, page extraction and consolidation are three prompts through one
OpenAI-compatible `/chat/completions` client, so a local `llama-server` is a
base URL and a model name. Embeddings were already local, so with this
configured **nothing in the harness leaves the machine**.

```bash
GATEWAY_PORT=8081 ./scripts/run_local.sh        # llama.cpp wants 8080
GATEWAY_URL=http://127.0.0.1:8081 \
EXTRACTOR=llm LLM_BASE_URL=http://127.0.0.1:8080/v1 \
EXTRACTION_MODEL=<your model> LLM_API_KEY=local LLM_TIMEOUT_SECS=300 \
  ./scripts/hands_on.sh
```

Three things that cost time once:

- **llama.cpp's default port is 8080, which is the gateway's.** The collision
  looks like a gateway bug, because `/health` still answers — with the wrong
  JSON. Move one of them.
- **`LLM_TIMEOUT_SECS=60` assumes a hosted provider.** One record through a
  partly-offloaded 26B took 51s, so the shipped default is about one slow record
  from an error that reads like the server being down.
- **A key is required even where it is ignored.** The extractor refuses to
  construct without one rather than sending an unauthenticated request to
  wherever `LLM_BASE_URL` happens to point. Any string does.

## The explorer

`GET /explorer` serves one self-contained HTML page — no build step, no npm, no
CDN, a hand-rolled force layout. Paste a grant token and a node id (or ask a
question and pick a seed from the answer's citations) and it draws the
**permission-filtered** neighbourhood.

It is served by the orchestrator because it reads localhost-only data under a
grant token typed into it; there is nowhere external it could be hosted without
moving both off the machine.

<Note>
**What it shows:** exactly what the pasted grant can see.
**What it does not:** objects the grant denies. Those are not drawn, not greyed
out, and not placeheld — but when any exist the page says so in a banner, with
the count of hidden nodes and dropped edges and the deny reasons. A filtered
subgraph rendered as if it were the whole graph is the one lie the tool must not
tell.
</Note>

## Gateway

Host-side. Owner sessions are bearer tokens; grants are introspected, never
minted.

| Route | Auth | Purpose |
| --- | --- | --- |
| `GET /health` | — | liveness |
| `GET /auth/authorize` | — | build the provider consent URL (PKCE + signed, expiring state) |
| `GET /auth/callback` | signed state | exchange the code **in the enclave**, persist the sealed refresh token, issue an owner session |
| `POST /auth/session` | — | verify identity via the enclave, issue an owner session JWT |
| `POST /auth/session/introspect` | — | resolve an owner session to its owner id |
| `POST /identity/verify` | — | the direct identity path, for a token obtained elsewhere |
| `POST /memory/seal/encrypt` | owner session | seal raw content; the owner comes from the session, not the request |
| `POST /memory/seal/decrypt` | owner session | unseal **record content**, never a refresh token |
| `POST /memory/seal/unseal` | **agent grant** | the same, authorised by a grant whose scope says `may_unseal`; the owner comes from the verified scope |
| `POST /memory/act` | **agent grant** | verify the grant, check it names this action, and have the enclave perform it. Returns an acknowledgement, never a credential |
| `POST /auth/device/register` | owner session | register a device public key |
| `GET /auth/device/keys` | owner session | list device keys, including revoked |
| `POST /auth/device/revoke` | owner session | revoke a key, and every grant it signed |
| `POST /memory/evaluate` | **agent grant** | one permission verdict per object, computed in the enclave against its own clock (ADR 0028). The scope comes from the verified grant and there is no field for one |
| `POST /memory/evaluate-write` | **agent grant** | the same for one write intent. `intent.owner_id` is overwritten from the verified scope, not compared against it |
| `POST /memory/scope/introspect` | — | resolve a grant token to `{active, scope, key_id}` |

<Note>
`POST /memory/scope/grant` **does not exist**. Grants are signed by a key the
owner holds; the gateway can verify one and cannot produce one. A test holds its
absence.
</Note>

## Orchestrator

| Route | Shape | Auth | Purpose |
| --- | --- | --- | --- |
| `GET /health` | sync | — | status of Neo4j, Redis and the gateway |
| `GET /sources` | sync | — | the connector registry, with `ENABLED_SOURCES` applied |
| `POST /ingest` | **enqueued** (202, job id) | **owner session** | run the ingestion graph for one source. The owner is derived from the session |
| `GET /ingest/{job_id}` | sync | **owner session**, as `Authorization: Bearer` | job status and result. Another owner's job answers 404, not 403 |
| `POST /remember` | sync (201) | **owner session** | push one thing the person said. Metered per owner |
| `POST /query` | sync | grant | run the query graph |
| `POST /memory/shift` | sync | grant | why a decision shifted: the chain and the evidence at each step |
| `POST /memory/context` | sync | grant | the citation chain around one object, across sources |
| `POST /memory/neighbourhood` | sync | grant | nodes and typed edges within `hops` of seeds, permission-filtered |
| `POST /memory/brief` | sync | grant | what an agent should know before acting: relevant claims, conflicts, who decided them and on what basis |
| `POST /memory/decide` | sync (201) | grant with `may_write` | record what an agent decided, and why. A refusal returns `refused: true` with its reason rather than a status code, because a decline is a real answer |
| `POST /memory/reads` | sync | **owner session** | what agents have actually read |
| `POST /memory/mutations` | sync | **owner session** | every state change, who made it, and which rule decided |
| `POST /memory/consolidate` | sync (201) | grant with `may_write` **and** `may_unseal` | turn one session's stored blocks into searchable claims. `errors` matters as much as `claims`: consolidation declines per conclusion, so a narrow grant yields a partial run |
| `POST /memory/sessions` | sync | **owner session** | what each agent has been working on, and whether it has been distilled. Holds no block content |
| `POST /memory/actions` | sync | **owner session** | every action the enclave performed, including the ones that failed. Carries a digest, never the arguments |
| `GET /explorer` | static | — | the read-only graph explorer |
| `GET /ui` | static | — | the owner's dashboard. Every path under it serves the same page, including `/ui/oauth/land` |

<Note>
**`owner_id` is not a field on any route.** It is derived from the credential —
a grant's verified scope, or an owner session resolved by the gateway. ADR 0027
closed the exception: `/ingest` and `/remember` used to take it from the body
and authenticate nothing, so naming somebody was enough to write into their
memory. The models now **forbid** unknown fields, so a caller still sending
`owner_id` gets a 422 naming it rather than a 201 that quietly ignored it.

`/remember` is metered per owner — `REMEMBER_RATE_LIMIT` per
`RATE_LIMIT_WINDOW_SECS`, refusing with 429 and `Retry-After`. A fixed window,
so a caller can get 2N across two adjacent windows; it is a ceiling to stop
loops, not traffic shaping.
</Note>

<Note>
Any grant-authorised read can answer **503** when `EVALUATE_IN_ENCLAVE` is on
and the enclave is unreachable: the permission verdict is computed in there and
there is no fallback to the host (ADR 0028). `retryable: true` distinguishes it
from a 403, which would mean the scope is too narrow.
</Note>

<Warning>
This does not make the orchestrator safe to expose. It has no TLS of its own,
no per-grant revocation, no per-owner quotas and no per-object deletion, and
`/ingest/{job_id}` returns a job's full result to its owner with no redaction.
</Warning>

### Why ingestion is enqueued and queries are not

Connecting a source means backfilling a large history in bursts, which is the
wrong lifetime for an HTTP request. An agent asking a question wants an answer,
not a job id.

### `POST /remember`

```json
{
  "session_token": "...",
  "text": "Decided that Kleos will use hybrid retrieval rather than pure vector search.",
  "source": "text",
  "occurred_at_ms": null,
  "sensitive": false
}
```

Runs **the existing ingestion graph** with the record pushed in rather than
pulled — extraction, resolution, sealing and the write are identical, because a
thing the person said is a record like any other once it exists.

- `external_id` is a **content address** over owner, source, text and timestamp.
  A retried request writes nothing new; the same sentence tomorrow is a second
  record, because it is.
- `url` stays `null` even when the text contains one. `SourceRef.url` means
  *where this record lives*, and an utterance lives nowhere. A URL inside it is
  something the person *referred to* — a different relationship.
- `sensitive` is per request, not per source. It used to be the only thing that
  required a session, which is how the unsealed path ended up writing to a
  named owner with no credential at all. The session is required either way now.

### `POST /query`

Returns an answer with citations, or an explicit decline listing why each
candidate was out of scope:

```json
{
  "question": "...",
  "answered": false,
  "text": "8 candidate memory object(s) matched, but none are within the requesting agent's scope (source not in scope)",
  "citations": [],
  "denied": [{"id": "...", "reason": "source_not_in_scope"}],
  "considered": 8
}
```

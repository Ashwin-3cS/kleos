## Sources and tools

| Variable | Default | Notes |
| --- | --- | --- |
| `ENABLED_SOURCES` | empty | empty means every registered connector. Narrowing is explicit |
| `ENABLED_TOOLS` | empty | empty means every registered tool. Narrowing is how a deployment switches off outbound fetching |
| `CHATGPT_EXPORT_DIR` | unset | unset means the connector fails **with the export instructions** — that error *is* the onboarding flow for this source |
| `CHATGPT_SENSITIVE` | `true` | should stay true; see [the orchestrator](/architecture/orchestrator) |
| `ENRICH_FROM_URLS` | `false` | off by default: it reaches the open web on the person's behalf, which should be an explicit choice rather than something a fresh checkout does |
| `FETCH_TIMEOUT_SECS` / `FETCH_MAX_BYTES` / `FETCH_MAX_REDIRECTS` | `15` / `2000000` / `3` | guards, not tuning |

## Agent sessions

| Variable | Default | Why this default |
| --- | --- | --- |
| `AGENT_SESSION_MAX_BLOCKS` | `400` | deliberately **below** `MAX_PATCHES_PER_QUILT` (660), so a session never silently splits across two Quilts |
| `AGENT_SESSION_MAX_BYTES` | `2000000` | per block; an over-cap block is refused rather than truncated |
| `AGENT_SESSION_TTL_SECS` | `3600` | clamped by the grant's own expiry |

## Storage at rest

| Variable | Default | Notes |
| --- | --- | --- |
| `ENCRYPT_CONTENT_AT_REST` | `false` | Off by default because the smoke script and the eval run without a gateway. **A deployment holding real memory sets it.** With it on and the gateway down, ingestion fails rather than quietly writing plaintext |
| `BLOB_STORE_DIR` | `.local/blobs` | These bytes arrive already encrypted, so this directory holds no plaintext — but it holds the **only** copy of a sensitive record's body. Back it up |
| `WALRUS_PUBLISHER_URL` / `WALRUS_AGGREGATOR_URL` | unset | When set, sealed blobs go to Walrus. Still a stub: it **raises** rather than silently falling back to `BLOB_STORE_DIR` |
| `SEALED_TOKEN_STORE_URL` | unset | Unset means an in-memory store, which silently forgets tokens on restart |

## Signing in

| Variable | Default | Notes |
| --- | --- | --- |
| `LOCAL_ENROLMENT` | on under `mock`, off under `nitro` | Enables `/auth/local/enrol` and `/auth/local/session`, which turn a device keypair into this install's owner (ADR 0029). A hosted deployment leaves it off: it uses OAuth, and an open enrolment route would mint owners for anyone who can reach it |
| `ENROLMENT_CODE_PATH` | `.local/enrolment-code` | Written on first start, mode `0600`, and **consumed by the first device that enrols**. Delete it and restart to enrol a different owner |
| `ALLOW_MOCK_IDENTITY` | `false` | Whether `mock_google_<subject>` is accepted at `/auth/session`. The owner id is a deterministic hash of the subject, so an accepted mock token is a derived identity rather than a guessed one. `run_local.sh` sets it for the smoke scripts and the dashboard's development sign-in |

## Where the services listen

| Variable | Default | Notes |
| --- | --- | --- |
| `GATEWAY_BIND` | `127.0.0.1` | The interface the gateway listens on. It was `0.0.0.0` and hard-coded; on a laptop in mock mode that put every route on the local network, where `mock_google_<subject>` is a valid sign-in. A server that must be reachable sets this **and puts TLS in front**, because a grant travels in a request body. The gateway logs a warning when it is bound beyond loopback |
| `ORCHESTRATOR_HOST` | `127.0.0.1` | Same argument, and it was already loopback |

The enclave's own listener is always loopback and has no setting: under `nitro`
the only thing dialling it is socat inside the enclave (`TCP:localhost:4000`),
and under `mock` it is the gateway on the same machine.

## Permission verdicts

| Variable | Default | Notes |
| --- | --- | --- |
| `EVALUATE_IN_ENCLAVE` | `false` | Computes `evaluate` and `evaluate_write` inside the TEE, against **the enclave's own clock** (ADR 0028). Off by default because the eval harness and the tests run with no gateway. With it on and the enclave unreachable, a read refuses with 503 — there is deliberately no fallback to the host |

## Rate limits

Per owner per window, on the owner-driven write routes (ADR 0027). `0` disables
one. A fixed window, so a caller can get 2N across two adjacent windows — it is
a ceiling to stop loops, not traffic shaping. It **fails open** if Redis is
unreachable: see `jobs/limits.py` for why.

| Variable | Default | Notes |
| --- | --- | --- |
| `REMEMBER_RATE_LIMIT` | `120` | `POST /remember` is synchronous and spends an extraction call per record |
| `INGEST_RATE_LIMIT` | `30` | `POST /ingest` only enqueues, so the ceiling is about queue depth |
| `RATE_LIMIT_WINDOW_SECS` | `60` | shared by both |

## Attestation verification

Read by the gateway and the orchestrator, and set by flags on `kleos-device`.
ADR 0026 has the reasoning; `/status` has what is reachable today.

| Variable | Default | Notes |
| --- | --- | --- |
| `VERIFY_ATTESTATION` | `true` | Off relays documents without reading them. The gateway logs a warning on boot when it is off |
| `ATTESTATION_ALLOW_MOCK` | `false` | `MOCK_ATTESTATION_...` is refused unless this is on. **Required with `ENCLAVE_MODE=mock`**, which is why `run_local.sh` and `hands_on.sh` set it — and why the prefix is a check rather than a comment |
| `ATTESTATION_ROOT_PATH` | unset | The AWS Nitro root, DER or PEM. Refused **at boot** unless it matches the fingerprint pinned in `shared/src/attestation.rs`, so a wrong certificate stops the service instead of failing every document. Fetch it from [AWS](https://aws-nitro-enclaves.amazonaws.com/AWS_NitroEnclaves_Root-G1.zip) |
| `ATTESTATION_EXPECTED_PCR0` | unset | Hex PCR0 of our own image. Without it, a verified document proves only that *some* Nitro enclave produced it — which does not exclude one the operator built |
| `ATTESTATION_MAX_AGE_SECS` | `300` | `0` disables the check. A document is a statement about the past, and a replayed one verifies perfectly |

<Note>
There is deliberately **no** `SEALED_TOKEN_STORE_URL` in the orchestrator's
configuration. The gateway's sealed refresh tokens are Postgres rows the
orchestrator must never read; giving Python credentials for that database would
defeat the point of doing the code exchange inside the enclave.
</Note>

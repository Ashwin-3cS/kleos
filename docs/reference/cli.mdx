## kleos-device

The owner's side of grant signing. A device holds the private key; the gateway
only ever sees the public half.

| Command | Purpose |
| --- | --- |
| `keygen --out <path>` | generate an Ed25519 keypair. Refuses to overwrite, writes `0600` |
| `pubkey --key <path>` | the base64 public key, for registration |
| `key-id --key <path>` | the derived key id, which is what the gateway reports |
| `sign --key <path> --scope <file> --ttl-secs 3600` | sign a scope into a grant token |
| `pubkey --key <path> --encryption` | the X25519 half, which receives sealed answers |
| `unseal --key <path>` | open a sealed answer on stdin, after verifying what sealed it |
| `verify --key <path>` | the same checks, printing the verdict and opening nothing |
| `enrol --key <path> --code <code>` | the body for `POST /auth/local/enrol`: turns this keypair into the install's owner |
| `sign-session --key <path>` | a signed assertion for `POST /auth/local/session` |

`sign` reads a `Scope` as JSON from a file or stdin and generates a fresh nonce
per grant, so two grants over an identical scope stay distinguishable in the read
log.

`unseal` takes what `query_memory` returns — the sealed envelope, the
attestation and the enclave key together — and **verifies before it opens**
(ADR 0026). This is the check that means something: the device is the one party
in the system that is not the operator.

| Flag | Effect |
| --- | --- |
| `--allow-mock` | accept a `MOCK_ATTESTATION_` stub. Needed against a local mock enclave, and refused without it |
| `--root <path>` | the AWS Nitro root, DER or PEM, checked against the pinned fingerprint |
| `--pcr0 <hex>` | require this measurement. A document that verifies but measures another image is refused, not downgraded |
| `--max-age-secs <n>` | reject a document older than this |
| `--allow-unattested` | open an answer that carries no attestation at all. The old behaviour, now something you ask for |

Two checks run, and the second is the one easy to omit: the document has to
verify, **and** it has to commit to this ciphertext sealed to this device. A
relayed document from another assembly verifies perfectly and is refused here.

### Signing in to a personal install

No OAuth app (ADR 0029). The gateway writes an enrolment code on first start;
the first device to present it becomes the owner, and the code is consumed.

```bash
kleos-device keygen --key ~/.kleos/device.key
kleos-device enrol  --key ~/.kleos/device.key --code "$(cat .local/enrolment-code)" \
  | curl -sS -X POST http://127.0.0.1:8080/auth/local/enrol \
      -H 'content-type: application/json' --data @-

# afterwards
kleos-device sign-session --key ~/.kleos/device.key \
  | curl -sS -X POST http://127.0.0.1:8080/auth/local/session \
      -H 'content-type: application/json' --data @-
```

`enrol` and `sign-session` **print a body rather than posting it**. This crate
holds a key and produces bytes; it has no HTTP client, which is also why ADR
0029 chose a signed assertion over a challenge round trip.

The owner id is `hex("local:<key_id>")`, so it is the key rather than a name —
two installs cannot collide, and nobody picks it.

## Scripts

| Script | Purpose |
| --- | --- |
| `scripts/kleos.sh {up,down,status,doctor,enrol,agent,logs}` | **the personal install.** One command for the whole stack, with a preflight that catches a stale process holding a port and warns when sealing is on. `enrol` makes a keypair the owner; `agent` mints a grant and prints the `claude mcp add` line |
| `scripts/services.sh {up,down,reset,status}` | Neo4j, Redis and Postgres without the compose plugin. Waits for every port. Detects a pre-rename container set |
| `scripts/run_local.sh [--with-orchestrator]` | enclave + gateway in mock mode; optionally the services too |
| `scripts/smoke_test.sh` | mock tokens and the mock OAuth connect flow |
| `scripts/orchestrator_smoke.sh` | identity → ingest → grant → query → decline → shift → neighbourhood → read log |
| `scripts/mcp_smoke.py` | drives the MCP server from a **real client**: two devices, a decision, and the briefing that tells the second what the first decided |
| `scripts/build_enclave.sh` | stagex/docker build producing a reproducible `.eif` |
| `scripts/deploy.sh` | ship the `.eif` and gateway binary to `DEPLOY_HOST` |
| `scripts/parent_forwarder.sh` | host-side VSOCK↔TCP bridging, both directions |
| `scripts/view_logs.sh` | enclave log forwarding |

<Note>
`run_local.sh` writes pid files under `.local/`, so stopping is
`kill $(cat .local/enclave.pid) $(cat .local/gateway.pid)` — or
`./scripts/kleos.sh down`, which stops all four and then **checks the ports
actually came free**. A pid file is a claim about what was started; the port is
the fact, and anything still holding one is what the next `up` would silently
inherit.
</Note>

## Repository layout

```
enclave/      Axum server inside the Nitro Enclave (or locally in mock mode)
gateway/      Axum server on the host, proxies to the enclave
shared/       Types shared by both: identity, memory schema, permissions, VSOCK envelopes
orchestrator/ Python orchestration service; not in the cargo workspace
              graphs/     ingestion, query, history, neighbourhood
              storage/    Neo4j, the sealed-blob store, the read log, agent sessions
              eval/       the labelled corpus and the RAG comparison
              static/     the graph explorer, one file, no build step
docs/         this documentation
scripts/      build/run/deploy/smoke-test plumbing
```

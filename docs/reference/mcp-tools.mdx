---
title: "MCP tools"
description: "The six tools an agent can call, and the ones that deliberately do not exist."
---

Served over stdio by `python -m orchestrator.mcp_server`.

<Warning>
Every tool takes a `grant_token`, and it is required on every one. MCP carries
no credential channel, so a `session_id` alone never authorises anything.
</Warning>

## Reads

<AccordionGroup>
<Accordion title="query_memory(question, grant_token, top_k=8)">
Query the owner's memory within the scope of a grant. Returns an answer with
citations, or an explicit refusal listing why each candidate was out of scope.

A refusal **is a real answer**: the tool never guesses at what it was not
allowed to read.
</Accordion>
<Accordion title="why_this_shifted(claim_id, grant_token)">
The ordered supersession chain for one claim, and at each step the citations that
appear in the superseding claim and not in the one it replaced — the evidence
that moved the decision.

Accepts the current claim, the original, or anything in between. Links the grant
does not cover come back **withheld**, with a reason and no content, rather than
being silently dropped from the chain.
</Accordion>
<Accordion title="memory_context_chain(object_id, grant_token, hops=3)">
What an object was derived from and what was derived from it, walked over
citation edges. Chains cross sources wherever the material does.
</Accordion>
</AccordionGroup>

## Session state

<AccordionGroup>
<Accordion title="open_session(grant_token)">
Returns `session_id`, `agent_id`, `device_id`, `identity_basis`,
`expires_at_ms`, `max_blocks`, `max_bytes`.

The session id is minted, never accepted from the caller. `identity_basis` is
`device_key` when the gateway verified a signature against a registered key —
rely on it — or `label` when all that is known is the unauthenticated `agent_id`.
</Accordion>
<Accordion title="append_context(session_id, grant_token, block)">
Appends one block of working context: the turn just taken, what a tool returned,
a scratchpad, the contents of a file.

Stored sealed, and **not searchable** — the response says so explicitly. A block
over the byte cap is refused rather than truncated.

Deliberately not gated on a write-capable grant: appending to your own
scratchpad produces nothing searchable, nothing carrying an ACL and nothing the
resolver sees.
</Accordion>
<Accordion title="close_session(session_id, grant_token, consolidate=False)">
Closes the session. Its blocks stay stored and stay unsearchable.

`consolidate=True` reads the blocks back and keeps whatever the session
concluded that outlives it — as ordinary kinded claims, attributed to this
device, resolvable against the person's own decisions. It needs the same
`may_write` a direct write does.

Consolidation runs **before** the close, so a failure leaves the session open
and retryable rather than closed with its work lost.

<Note>
`consolidate=False` is the right default. Most sessions conclude nothing, and
what an agent definitely wants remembered it says outright with
`record_decision` rather than hoping consolidation notices.
</Note>
</Accordion>
</AccordionGroup>

## Before acting

<AccordionGroup>
<Accordion title="brief_before_acting(intent, grant_token, session_id=None, top_k=8, include_body=False)">
**The point of the harness.** Called *before* acting, with an intent rather than
a question — "I am about to pick a database for Lantern" — because the thing an
agent most needs to know is the thing it does not know to ask about.

Returns what is relevant with citations, the supersession chains those claims sit
in, who changed each one and on what basis, and `advisories`: one rendered line
each, ready to put into a context window without parsing anything.

```
device 3f9adead1c (labelled 'claude-code', device-authenticated) recorded
"project Lantern will use Neo4j." because "graph proximity is a hard
requirement and Postgres cannot do it" [rule: agent_delegate_supersedes].
Be aware of this before acting.
```

Every advisory names the **device** and says whether that identity is
authenticated — `device-authenticated` means a signature was verified against a
key the owner registered; "label only" means all that is known is a string the
owner typed.

Composed from `run_query` and `why_did_this_shift` rather than retrieving for
itself, so each keeps its own permission check and its own log entry. One extra
entry records the composite, which is what lets an owner see what the agent was
*about to do*.

<Note>
A conflicting decision outside the grant comes back **withheld**, not omitted:
the agent is told it exists and that it may not read it. An agent told "no
conflicts" acts; an agent told "a conflict you cannot see" asks.

There is deliberately **no structure** in the result — no adjacency, no node
lists. An agent that could walk the graph could map a memory it cannot read.
</Note>

<Warning>
A briefing is only as selective as the ranking underneath it. Retrieval returns
its best `top_k` rather than gating on relevance, so an agent briefing on an
unrelated intent is still told about the decisions that exist. That is the right
failure direction — too much context rather than a missed conflict — but it is a
property of the ranking, and in mock mode the embeddings are hashed tokens and
barely selective at all.
</Warning>
</Accordion>
</AccordionGroup>

## Writing

<AccordionGroup>
<Accordion title="record_decision(grant_token, statement, reason, session_id=None, memory_kind='episodic', sensitive=False)">
Records a decision the agent has just made, and why.

`statement` is the decision as a durable assertion — "Lantern uses Neo4j", not
"I think we should probably use Neo4j". **`reason` is required**: the next
agent's briefing is built out of it, and a stored decision with no stated basis
tells that agent nothing it can act on.

Three things the agent **cannot** choose, and they are what make the write safe:

| | |
| --- | --- |
| **Whether it may write** | Needs `may_write` in the grant. Deny-by-default, so every grant issued before that field existed is read-only. The refusal names the reason. |
| **What source it writes as** | Always `agent`. `Scope.write_sources` is a separate set from `Scope.sources` so an agent permitted to *read* the person's typed notes cannot write a claim that claims to be one. |
| **Its own precedence** | Taken from the grant. Without `may_supersede_owner` the claim is `reference` and **contradicts** the owner's conflicting decision rather than replacing it — both sides kept. With it, the agent is a `delegate` and may supersede. Nothing in the statement can change this; it is stamped at the one point input becomes a candidate. |

`memory_kind` is `episodic`, `procedural` or `tacit`. A tacit claim is an
inference *about* the person rather than something they said, so labelling one
raises its sensitivity — on the stored object as well as at the gate.

The declaration is taken as given rather than rediscovered by extraction: an
agent calling this has already said the sentence is a decision, and asking an
extractor to notice would make the one path with an explicit declaration the
least reliable in the service. Everything else — subjects, citations,
resolution, the write — is the ordinary ingestion path.

<Warning>
`sensitive=True` is **refused**. Sealing a body needs an owner session and an
agent holds a grant, so there is no path by which it can be sealed today. Refused
up front rather than skipped inside the graph, where it would read as a partial
success.
</Warning>
</Accordion>
</AccordionGroup>

## What deliberately does not exist

| Absent tool | Why |
| --- | --- |
| a neighbourhood tool | It is a visualization payload. An adjacency list answers no question an agent has, and exposing one hands agents a cheap structure-enumeration primitive — seed, walk, re-seed — for no gain in answer quality. |
| a read-log tool | An agent that could read the log would see which objects *other* agents were shown, which is a disclosure channel around the permission check rather than a record of it. It needs an owner session. |
| a mutation-log tool | Sharper version of the same: read wholesale it would tell one agent what every other agent has been writing. A briefing surfaces mutations only for objects the asking agent was just permitted to see. |
| a second write tool | One write, so the gate, the precedence class and the `agent` source are enforced in one place. A test asserts no other tool looks like a write path. |

<Note>
A test asserts the exact tool set **and** that these names stay absent. An
absence recorded only in a docstring is one the next person removes by accident.
</Note>
